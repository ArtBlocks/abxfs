ABX FS is deployed on production networks and their testnets, at the same addresses
on each; [Deployments](/docs/reference/deployments) lists them. Every command below
takes the production or test network of your choice. The testnets take faucet ETH,
and are the place to try things first.

<Callout type="warn">
**Prerelease, and unaudited.** ABX FS is early software and may have bugs; we do
not guarantee it is bug-free. Its contracts have had internal reviews but no
independent security audit; ABX, which every org is built on, has had none either.
Everything you publish is public and permanent: nothing on chain can be edited or
deleted, by you or by us. On a production network you are spending real funds;
try things on a testnet first.
</Callout>

## Two layers, kept separate

The distinction worth learning before anything else:

- **Content** is permissionless and immutable. Anyone can write bytes; they are
  addressable by CID forever; nothing owns them.
- **A project** is an [ABX](https://docs.abx.io) NFT inside an **org**. Its owner
  publishes root CIDs to it and moves tags. `ownerOf` is the entire authorization
  model.

Content does not need a project to exist or resolve. A project is one
representation of content, and anyone can build a different one.

## The CLI

The `abxfs` CLI uploads, publishes, diffs, verifies and pins. It needs Node 22.13 or later:

```bash
npm install -g @artblocks/abxfs-cli
```

Reads need nothing else; the canonical addresses are compiled in. `--chain`
names the network, and there is no default: a command without one lists the
names (set `ABXFS_CHAIN` to name it once for the shell). Project commands need an org:

```bash
abxfs read <root> --path index.html --chain <network>
abxfs info --project-id 0 --org <org> --chain <network>
```

Writes are signed by a private key you hold, in the environment only: the CLI never reads one from disk. (On
fs.abx.io they are signed by your browser wallet.)

To try it on a testnet, make a key just for that, and keep it out of files and shell history:

```bash
export ABXFS_PRIVATE_KEY=0x$(openssl rand -hex 32)       # a new key, for this shell only
abxfs upload ./site --chain <network> --dry-run          # compute CIDs and count the transactions, spend nothing
abxfs upload ./site --chain <network> --name my-project  # mint and publish
```

An account with no ETH is refused before anything is sent, and the refusal names its address: fund that address from
a faucet for the testnet you chose (the network's own documentation lists them). On a layer-2 testnet, publishing a
four-file site as a new project in a new org (nine transactions) measured 0.000026 ETH, so 0.001 is plenty.

With `--name` and no `--org`, the upload uses `ABXFS_ORG` or the `org` in your config if
you set one and it belongs to the current factory, else the newest current-factory org you administer. If you administer none on that factory, your own
**org** is created in the same transaction as the project, so there is no extra
signature.

The upload is chunked, deduplicated against what is already on chain, and
compressed per chunk with FastLZ by default (the chain inflates it itself). Before
it sends anything it prints the plan (network, org, transactions, the likely cost at
the current gas price, and the most it could cost if fees spiked) and asks you to type
`yes`; in a script, pass `--yes`. A big folder is not
refused; it is more transactions, and running the same upload again after an
interruption sends only what is missing.

When the project is published, the CLI prints where it is: the token's `animation_url`
(the live site) and its page on the app. `abxfs info` prints both again later.

`--dry-run` runs the whole pipeline offline, so you can see the root CID and the
transaction count, the project's own transactions included, before committing to either. To try everything against a local
chain instead, `abxfs dev` runs Anvil with the contracts deployed (see the
[CLI reference](/docs/reference/cli)).

## Read it back

When it finishes you get a root CID. Reading is permissionless and needs no wallet,
no key, and no configuration. A gateway resolves any stored content by CID, whether
or not a project points at it, from the content's own host (the chain id and the root,
base32-encoded, as one DNS label):

```
https://<chain id>-<base32 root>.<content domain>/index.html
```

Nothing about a gateway is privileged: [run your own](/docs/using-abxfs/run-a-gateway),
or skip it and read the bytes from contract storage with `abxfs read`.

## In the browser

[fs.abx.io](https://fs.abx.io), Art Blocks' hosted app, does the same upload and
publish in the browser, with no install.
